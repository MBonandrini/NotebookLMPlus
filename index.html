Setup tutorial

1. Install Ollama

Install Ollama on the machine that will run the local model. Ollama exposes its local API on http://localhost:11434/api by default.

This browser-only version does not require Python, FastAPI, a local bridge, or a separate desktop helper.

Windows

  1. Download and install Ollama from the official Ollama website.
  2. Launch Ollama once after installation.
  3. Leave Ollama running while using NotebookLM+.

Linux

curl -fsSL https://ollama.com/install.sh | sh

macOS

Install the Ollama application, open it, then continue to the next step.

2. Run the automatic Ollama setup (Windows)

This is the recommended Windows setup. It replaces the manual OLLAMA_ORIGINS configuration.

One-click setup: download the ZIP, extract it, then double-click Run-Ollama-Setup.bat.

Download automatic Ollama setup

The script is preconfigured for https://MBonandrini.github.io/NotebookLMPlus/. It preserves existing Ollama origins, adds only the trusted GitHub Pages origin, restarts Ollama, optionally downloads the recommended models, and tests the local API plus browser-origin/CORS response.

No Administrator rights are normally required because the setting is written for the current Windows user. The source scripts are included under tools/ollama-setup/ for inspection.

The script deliberately does not set OLLAMA_ORIGINS=*.

3. Download a chat model and embedding model

If you chose model installation in the automatic setup, you can skip this step. Otherwise install one model for answers and one embedding model for semantic search.

Recommended starting point

ollama pull qwen3:4b
ollama pull embeddinggemma

On slower machines, choose a smaller chat model. On a stronger workstation, select a larger installed model from AI / Ollama Configuration.

4. Manual origin setup (only if needed)

Windows users should normally use the automatic setup in step 2. This section is for Linux, macOS, custom domains, or manual configuration.

For the NotebookLM+ site, the GitHub Pages origin is:

https://MBonandrini.github.io
Prefer the exact trusted origin. Do not use * unless you understand the security implications.

Windows / PowerShell

setx OLLAMA_ORIGINS "https://MBonandrini.github.io"

Fully quit and restart Ollama afterward.

Linux

OLLAMA_ORIGINS=https://MBonandrini.github.io ollama serve

macOS

Set OLLAMA_ORIGINS for the Ollama process/service and restart Ollama.

5. Connect and test

  1. Open AI / Ollama Configuration.
  2. For local modes keep provider Ollama and endpoint http://127.0.0.1:11434.
  3. Press Test connection.
  4. Press Refresh installed models.
  5. Select the chat and embedding models.
  6. Press Save AI settings.

Your browser may separately request permission for the GitHub Pages site to communicate with software on localhost/local network. Approve that permission for your trusted deployment.

6. Create your first notebook

  1. Open Workspace.
  2. Press + next to Notebooks.
  3. Give the notebook a name and optional instructions.
  4. You can later clone it, save it as a template, or create another notebook from that template.

7. Link folders and files

Use Add files or Add folder. Where supported, the app stores a permissioned file-system handle rather than copying the original data into the website.

Supported browser parsing includes PDF, DOCX, XLS/XLSX, PPTX, CSV, TXT, Markdown, JSON, HTML and XML. Legacy .doc and .ppt should be converted first.

Nothing is uploaded to GitHub. Parsing, chunking, embeddings, notebook metadata and chat history stay in browser storage unless you deliberately configure a remote model endpoint.

9. Configure a hosted AI engine

Choose Hosted AI Engine from the mode dropdown. The default provider is Hosted AI (OpenAI-compatible).

  1. Enter an HTTPS API base such as https://ai.example.com/v1.
  2. Enter a session API token if the server requires one. NotebookLM+ does not persist it.
  3. Press Discover hosted models, or type the chat model name manually.
  4. Optionally enter an embedding model. If left blank, keyword retrieval remains available.
  5. Press Test connection and then Save AI settings.
Static-site credential warning: do not distribute a permanent provider secret inside the GitHub Pages code. For a future commercial/hosted service, use short-lived user tokens, an authenticated gateway, or another server-side access layer.

The hosted endpoint must allow CORS from this NotebookLM+ site. The browser sends only retrieved context for chat, except when you deliberately configure hosted embeddings.

10. Troubleshooting

“Ollama offline”

Run the automatic setup again, confirm Ollama is running, then use Test connection. For a custom deployment, confirm its exact origin is present in OLLAMA_ORIGINS.

Hosted AI cannot connect

Check the HTTPS endpoint, API token, model name, and that the hosted service allows CORS from this NotebookLM+ origin.

Browser blocks localhost

Chrome/Edge may request local-network or loopback permission. Approve it for your trusted NotebookLM+ site. If the browser cannot access localhost, use Remote Ollama or Hosted AI Engine mode.

File or folder picker does not open

NotebookLM+ uses the browser's native file and directory inputs for maximum compatibility on GitHub Pages. Make sure a notebook is selected, then click Add files or Add folder again. Files are processed locally in the page; they are not sent to GitHub.

Responses are slow

Switch to Lightweight mode, reduce context tokens and top-K retrieval, choose a smaller Ollama model, use Remote Ollama, or configure a hosted AI engine.
